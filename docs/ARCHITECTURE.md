# Структура проекта

Bars Helper — приложение на TypeScript, React и Ink. Интерфейс терминала, сценарии работы и доступ к внешним системам разделены.

```text
src/
  cli.tsx                  Точка запуска и соединение зависимостей
  app/
    App.tsx                Каркас экрана: заголовок и содержимое
    AppContent.tsx         Выбор экрана, загрузка и сообщения
    use-app-model.ts       Связывает сценарии разделов
    use-global-input.ts    Главное меню и общие сочетания клавиш
    navigation.ts          Идентификаторы экранов и пункты меню
    components/            Заголовок, меню, подтверждение действия
    flows/                 Вход, выбор группы, посещаемость, расписание, оценки, сверка
    state/                 Навигация и выполнение операций
  features/
    auth/                  Вход, восстановление, интерфейсы хранилища
    attendance/            Посещаемость, список пар, черновики
    schedule/              Недельное расписание
    grades/                Оценки
    groups/                Выбор группы и область хранения черновиков
    integrity/             Сверка журнала и исправление нарушений
    mail/                  Почта и подготовка текста к показу
  domain/                  Модели, идентификация пар, даты и время
  infrastructure/
    bars/                  Клиент БАРСа, браузерная сессия, разбор HTML
    auth/                  Связка ключей, DPAPI, Touch ID
    mail/                  Клиент OWA, cookies, вход, разбор писем
  shared/
    hooks/                 Часы и размер терминала
    ui/                    Лоадер и анимация появления текста
    runtime/               Пути к ресурсам приложения
tests/                     Проверки поведения на тестовых данных
tests/integration/         Клиент БАРСа с локальным сервером и Chromium
scripts/                   Сборка, установка и отдельные служебные команды
```

## Кто чем владеет

`App` задаёт только общий вид страницы. `AppContent` выбирает конкретный экран; запросов к БАРСу в JSX нет. Сценарии из `app/flows` хранят данные своего раздела и выполняют его действия. `useAppModel` связывает их, например при смене аккаунта или восстановлении входа.

`useOperation` последовательно выполняет операции БАРСа, управляет загрузкой и сообщениями, обрабатывает истечение сессии и завершение работы. Раздел почты имеет собственный жизненный цикл загрузки внутри `MailView`.

`AttendanceController` владеет черновиками по сочетанию аккаунта, группы и учебной записи. `AuthService` управляет последовательностью входа и сохранения сессии через интерфейсы из `features/auth`. Реализации шифрования и Touch ID находятся в `infrastructure/auth`.

`BarsClient` загружает доступные учебные записи из профиля, сопоставляет их со статусами из списка студентов и получает идентификаторы групп из ссылок расписания. Выбранная группа проверяется по этому списку. `useGroups` восстанавливает выбор после завершения входа и Touch ID, а при смене группы сбрасывает данные разделов. Предпочтение хранится в `SavedAuth` вместе с сессией; оценки запрашиваются по выбранной учебной записи.

`BarsClient` реализует операции с данными. `BarsSession` отдельно владеет браузером, cookies, входом и двухфакторной проверкой. Функции подготовки формы посещаемости находятся в `attendance-form.ts`, разбор ответов БАРСа — в файлах парсеров. Проверки перед записью и чтение результата после неё остаются в клиенте.

## Зависимости

- `domain` содержит общие модели и правила, не импортирует React или внешние адаптеры.
- `features` использует предметные модели и интерфейсы, а не конкретные браузеры или системные хранилища.
- `infrastructure` реализует эти интерфейсы и преобразует ответы внешних систем в модели приложения.
- `app` связывает разделы через переданные зависимости; создание конкретных клиентов находится в `cli.tsx`. Отдельная команда `app/self-test.ts` проверяет доступность нативных компонентов сборки.
- `shared` содержит только действительно общие элементы. Специфичная для раздела функция остаётся рядом с этим разделом.

При добавлении раздела начни с `features/<имя>`, добавь сценарий в `app/flows`, пункт в `app/navigation.ts` и отображение в `AppContent`. При необходимости добавь интерфейс и его реализацию в соответствующий адаптер. UI-компоненты называются в `PascalCase`, остальные модули — в `kebab-case`.

## Форматирование и проверка

```bash
npm run format
npm run format:check
npm run typecheck
npm test
npm run test:integration
npm run build
```

Prettier и EditorConfig задают два пробела, переносы строк и единый стиль. TypeScript проверяет строгие типы и неиспользуемые объявления. Перед сборкой каталог `dist` очищается, чтобы после перемещения файлов в релиз не попадал старый код. Команда `bars` запускает собранную версию: после изменения исходников нужен `npm run build`.

Проверки используют тестовые данные. Интеграционные тесты требуют установленного Chromium (`npx playwright install --only-shell chromium`) и локального сервера; настоящий журнал не изменяется. Создание переносимых архивов описано в [руководстве по релизам](RELEASING.md).
